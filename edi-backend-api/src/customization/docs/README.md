# EDI Customization Layer Documentation

## Overview

The EDI Customization Layer is a powerful extension to the EDIFACT Parser that enables the transformation of comprehensive EDI data into customer-specific, document-specific XML outputs. This layer provides flexible configuration management, rule-based filtering, field mapping, and custom XML generation capabilities.

## Architecture Overview

The EDI Customization Layer follows a modular architecture with clear separation of concerns:

```
┌─────────────────────────────────────────────────────────────┐
│                    Customization Layer                      │
├─────────────────────────────────────────────────────────────┤
│  CustomizationProcessor (Main Orchestrator)                │
├─────────────────────────────────────────────────────────────┤
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ ┌────────┐ │
│  │ Data        │ │ Rule        │ │ Mapping     │ │ XML    │ │
│  │ Readers     │ │ Engine      │ │ Engine      │ │ Gen.   │ │
│  └─────────────┘ └─────────────┘ └─────────────┘ └────────┘ │
├─────────────────────────────────────────────────────────────┤
│  ConfigurationManager (Central Configuration)               │
└─────────────────────────────────────────────────────────────┘
```

### Key Features

- **Modular Design**: Each component has a specific responsibility
- **Configuration-Driven**: All behavior controlled through configurations
- **Extensible**: Easy to add new transformations, rules, and templates
- **Batch Processing**: Support for processing multiple files
- **Validation**: Multi-level validation (none, basic, standard, strict)
- **Multiple Formats**: Support for XML, CSV, and JSON input/output

## Core Components

### 1. Data Readers (`data_readers.py`)

Handles reading comprehensive EDI data from various formats:

- **XMLDataReader**: Reads XML files generated by the main EDIFACT parser
- **CSVDataReader**: Reads CSV exports of EDI data
- **JSONDataReader**: Reads JSON exports of EDI data
- **DataReaderFactory**: Auto-detects format and creates appropriate reader

### 2. Rule Engine (`rule_engine.py`)

Provides rule-based filtering and processing:

- **DocumentTypeFilter**: Filters by document type (ORDERS, INVOIC, etc.)
- **CustomerGLNFilter**: Applies customer-specific rules based on GLN
- **FieldExtractor**: Extracts specific fields based on rules
- **RuleEngine**: Coordinates all filters and rules

### 3. Mapping Engine (`mapping_engine.py`)

Handles field mapping and data transformation:

- **DataTransformer**: Applies various transformations (format, calculate, lookup, etc.)
- **FieldMapper**: Maps fields from source to target structure
- **MappingEngine**: Manages mapping configurations and applies them

### 4. XML Customizer (`xml_customizer.py`)

Generates custom XML based on templates:

- **TemplateProcessor**: Manages XML templates
- **XMLStructureValidator**: Validates XML structures
- **CustomXMLGenerator**: Generates XML from data and templates

### 5. Configuration Manager (`configuration_manager.py`)

Manages all configurations:

- **DocumentTypeConfig**: Document type specific settings
- **CustomerConfig**: Customer specific preferences
- **MappingConfig**: Field mapping configurations
- **ConfigurationManager**: Central configuration management

### 6. Customization Processor (`customization_processor.py`)

Main orchestrator that coordinates all components:

- **CustomizationProcessor**: Main processing engine
- **BatchProcessor**: Handles batch processing of multiple files
- **ProcessingResult**: Encapsulates processing results

## Getting Started

### Installation

The customization layer is part of the EDIFACT Parser package. No additional installation is required.

### Basic Usage

```python
from customization import CustomizationProcessor

# Create processor
processor = CustomizationProcessor()

# Process a file
result = processor.process_file(
    input_file="path/to/edi_data.xml",
    document_type="ORDERS",
    customer_gln="1234567890123"
)

if result.success:
    print("XML Output:")
    print(result.output_xml)
else:
    print("Errors:", result.errors)
```

### Configuration Setup

```python
from customization import (
    ConfigurationManager,
    create_orders_document_config,
    create_sample_customer_config
)

# Create configuration manager
config_manager = ConfigurationManager()

# Add document type configuration
orders_config = create_orders_document_config()
config_manager.add_document_type_config(orders_config)

# Add customer configuration
customer_config = create_sample_customer_config("1234567890123", "My Customer")
config_manager.add_customer_config(customer_config)
```

## Configuration Management

### Document Type Configuration

Document type configurations define the structure and rules for specific EDI document types:

```json
{
  "document_type": "ORDERS",
  "document_code": "850",
  "description": "Purchase Order",
  "required_segments": ["UNB", "UNH", "BGM", "DTM", "NAD", "LIN", "UNT", "UNZ"],
  "optional_segments": ["RFF", "CUX", "PAT", "TDT"],
  "business_rules": {
    "min_line_items": 1,
    "currency_required": true
  },
  "default_mappings": {
    "order_number": "business_data.references.ON",
    "order_date": "business_data.dates.137"
  }
}
```

### Customer Configuration

Customer configurations define customer-specific preferences and requirements:

```json
{
  "customer_gln": "1234567890123",
  "customer_name": "Global Retail Chain",
  "document_preferences": {
    "ORDERS": {
      "require_delivery_date": true,
      "max_line_items": 100,
      "currency": "USD"
    }
  },
  "transformation_rules": {
    "date_format": "YYYY-MM-DD",
    "include_empty_fields": true
  },
  "output_formats": ["xml", "json"]
}
```

### Mapping Configuration

Mapping configurations define how EDI fields are mapped to the target XML structure:

```json
{
  "config_name": "orders_global_retail",
  "document_type": "ORDERS",
  "customer_gln": "1234567890123",
  "field_mappings": [
    {
      "source_path": "business_data.references.ON",
      "target_path": "Header.OrderNumber",
      "transformation_type": "copy",
      "required": true
    },
    {
      "source_path": "business_data.dates.137",
      "target_path": "Header.OrderDate",
      "transformation_type": "format",
      "transformation_config": {
        "format_type": "date",
        "output_format": "%Y-%m-%d"
      }
    }
  ]
}
```

## Usage Examples

### Example 1: Basic Processing

```python
from customization import CustomizationProcessor

processor = CustomizationProcessor()

# Process EDI data
result = processor.process_file(
    "input.xml",
    document_type="ORDERS",
    customer_gln="1234567890123"
)

if result.success:
    # Save output
    with open("output.xml", "w") as f:
        f.write(result.output_xml)
```

### Example 2: Custom Template

```python
from customization import CustomizationProcessor
from customization.xml_customizer import XMLTemplate

# Create custom template
template = XMLTemplate(
    name="CustomOrder",
    root_element="Order",
    structure={
        "OrderInfo": {"Number": "string", "Date": "string"},
        "Customer": {"ID": "string", "Name": "string"},
        "Items": {"Item": [{"SKU": "string", "Qty": "string"}]}
    }
)

processor = CustomizationProcessor()
processor.add_custom_template(template)

# Process with custom template
result = processor.process_data(
    data,
    document_type="ORDERS",
    output_template="CustomOrder"
)
```

### Example 3: Batch Processing

```python
from customization.customization_processor import BatchProcessor

batch_processor = BatchProcessor()

# Process entire directory
results = batch_processor.process_directory(
    input_directory="./input_files",
    output_directory="./output_files",
    document_type="ORDERS",
    customer_gln="1234567890123",
    file_pattern="*.xml"
)

print(f"Processed {results['successful_files']} files successfully")
```

## API Reference

### CustomizationProcessor

Main processing class that orchestrates the entire customization workflow.

#### Methods

- `process_file(input_file, document_type, customer_gln=None, output_template=None, validation_level="standard")`: Process a single file
- `process_data(input_data, document_type, customer_gln=None, output_template=None, validation_level="standard")`: Process data directly
- `add_custom_template(template)`: Add a custom XML template
- `add_custom_mapping(mapping_config)`: Add a custom mapping configuration

### ConfigurationManager

Manages all configuration aspects of the customization layer.

#### Methods

- `add_document_type_config(config)`: Add document type configuration
- `add_customer_config(config)`: Add customer configuration
- `add_mapping_config(config)`: Add mapping configuration
- `export_configuration(output_file, format_type)`: Export all configurations
- `import_configuration(input_file, format_type)`: Import configurations

### DataReaderFactory

Factory for creating data readers based on input format.

#### Methods

- `create_reader(format_type)`: Create reader for specific format
- `auto_detect_format(source)`: Auto-detect format from file
- `read_data(source, format_type=None)`: Read data with auto-detection

## Troubleshooting

### Common Issues

#### 1. Configuration Not Found

**Problem**: `No mapping configuration found for ORDERS/1234567890123`

**Solution**: 
- Verify that the mapping configuration exists
- Check that the document type and customer GLN match exactly
- Use `list_mapping_configs()` to see available configurations

#### 2. Field Mapping Errors

**Problem**: `Required field missing: business_data.references.ON`

**Solution**:
- Check that the source data contains the required field
- Verify the field path is correct (use dot notation)
- Consider making the field optional or providing a default value

#### 3. XML Generation Errors

**Problem**: `Error generating XML: Invalid character in tag name`

**Solution**:
- Ensure field names are valid XML element names
- Use transformation rules to clean field names
- Check for special characters in data values

#### 4. Performance Issues

**Problem**: Processing is slow for large files

**Solution**:
- Use batch processing for multiple files
- Set validation level to "none" for performance-critical scenarios
- Consider processing files in parallel
